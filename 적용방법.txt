적용 방법
1. 이 ZIP을 압축 해제합니다.
2. 안의 파일과 폴더를 기존 프로젝트의 index.html이 있는 위치에 덮어씁니다.
   assets와 shared는 기존 폴더에 병합하세요. assets 폴더 전체를 교체하거나 지울 필요는 없습니다.
   index.html과 새 shared/*.js, assets/frames 두 폴더를 함께 적용해야 합니다.
3. GitHub Desktop의 Changes를 확인하고 Commit → Push origin을 누릅니다.
4. Render에서 해당 커밋 배포가 Live가 되면 폰과 아이패드 페이지를 모두 새로고침합니다.
   폰 https://test1-e3hn.onrender.com/
   아이패드 https://test1-e3hn.onrender.com/display.html?fish=fish05
   NFC https://test1-e3hn.onrender.com/?fish=fish05&phase=water
5. 아이패드에서 디스플레이 시작하기를 한 번 누른 뒤 테스트합니다.
   준비 화면에서 물 프레임을 미리 받습니다. 첫 접속의 로딩 시간은 연결 속도에 따라 달라집니다.

바뀐 동작
- 원본 S1_water.mp4의 134장을 추출했습니다. 별도로 사진을 준비할 필요가 없습니다.
- 폰에서 실제로 배출된 물의 비율 0~100%를 프레임 0~133에 직접 연결합니다.
  예: 50%는 67번 프레임, 100%는 133번 프레임입니다.
- 물이 멈추면 해당 사진을 유지하고, 빨리 부으면 그 양에 맞는 프레임으로 바로 이동합니다.
- 폰의 물이 모두 빠지고 아이패드에 마지막 프레임을 그린 다음 S1_main으로 넘어갑니다.
  프레임 로딩이 실패하면 이전 그림을 유지하고 다시 시도하며, 다음 장면으로 넘어가지 않습니다.
- 소녀 GIF의 59장을 Canvas에 그립니다. GIF 디코더와 CSS 색상 필터를 사용하던 경로를 대체했습니다.
  말풍선이 바뀌어도 소녀를 처음부터 재생하지 않고, 안내가 숨겨지면 재생을 멈춥니다.
- 기울이기는 즉시 적용되고 안내는 3초 후 0.6초 동안 한 번 사라집니다.
- S1_walk / S1_main / S1_ending은 기존 영상을 계속 사용합니다.
- 원래 영상/GIF 파일은 그대로 두어도 됩니다. 이번 ZIP에는 포함하지 않았습니다.
- 기존 로고·말풍선 위치와 호스 중앙 정렬, 마지막 초기화/TouchDesigner 흐름은 유지합니다.

나중에 수정할 곳
- 소녀 위치·크기: home-guide.css의 #homeGuideGif
- 소녀 색·속도: config.js의 home.guideFrames.color / fps
- 물이 빠지는 속도: config.js의 home.pourRate / pourBoost
- 물 프레임 경로·개수: sync-config.js의 fish.fish05.waterFrames
  현재 프레임은 960×720 WebP 134장입니다. 물고기별로 다른 waterFrames를 등록할 수 있습니다.
- 프레임 파일을 나중에 바꿀 때는 새 폴더명으로 prefix를 변경하면 이전 이미지 캐시와 섞이지 않습니다.

확인한 범위
- 실제 로컬 WebSocket 서버와 폰/아이패드 DOM 시뮬레이션으로 전체 흐름을 검증했습니다.
- 정확한 프레임 대응, 급격한 진행률 변경, 이전 프레임 유지, 재연결, 마지막 프레임 표시 전 전환 방지,
  소녀 25fps 루프, 안내 3초 페이드, 게임/ending/첫 화면 복귀, TD 신호 1회를 확인했습니다.
- 모든 193장 이미지의 개수·이름·해상도와 소녀 투명도 데이터에 빈 프레임이 없는 것을 확인했습니다.
- 버디3 및 실제 아이패드의 화면/GPU에서는 아직 확인하지 않았습니다. 적용 후 실기기 확인이 필요합니다.
