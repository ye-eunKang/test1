적용 방법
이 수정은 폰·아이패드·서버를 함께 바꿉니다. 아래 코드 8개를 모두 교체해주세요.

루트 폴더: index.html / home-guide.css / config.js / water-background.js / app.js / server.js / display.js
shared 폴더: phone-sync.js

1. ZIP의 폴더 구조 그대로 기존 프로젝트에 덮어씁니다.
2. GitHub Desktop에서 Commit → Push origin.
3. Render 배포가 완료되면 폰과 아이패드 페이지를 모두 새로고침합니다.
4. 아이패드에서 디스플레이 시작하기를 누른 뒤 NFC 플로우로 테스트합니다.

수정 내용
- GIF는 기존 여러 색상 필터를 같은 색을 내는 단일 SVG 필터로 정리하고 별도 합성 계층으로 표시합니다.
- GIF에는 반복 투명도 애니메이션을 적용하지 않습니다. 물 기울이기 안내의 3초 후 페이드는 부모에서 한 번 적용됩니다.
- 폰에서 빠져나간 물의 비율(0~100%)과 배출 속도를 아이패드로 전송합니다.
- S1_water의 진행 위치/배속이 물의 양을 따라갑니다. 빠르게 많이 부으면 영상도 빠르게 따라옵니다.
- 물을 멈추면 영상도 현재 배출량에 해당하는 위치에서 멈춥니다.
- 물이 많이 넘칠수록 배출 속도가 커집니다. 물은 화면 위 가장자리에 닿았을 때만 빠집니다.
- 기존 잔량 35% 완료 조건을 물이 모두 빠지는 조건으로 변경했습니다. 가장자리의 1% 미만 잔량은 0으로 정리합니다.
- 물이 다 빠져도 아이패드에서 물 영상의 마지막 부분이 실제로 끝나기 전에는 다음 영상으로 넘어가지 않습니다.
- 다음 main 영상은 정상 1배속으로 재생됩니다.
- 재접속하면 저장된 배출 비율을 복원합니다.

조정할 값
config.js의 home.pourRate: 기본 물 배출 속도
config.js의 home.pourBoost: 많이 기울였을 때의 배출 속도 증가

검증
- 실제 S1_water: 11.166667초 / 12fps / H.264.
- GIF 원본 59프레임을 검사했고 완전히 빈 프레임은 없었습니다.
- 모의 폰·아이패드와 실제 로컬 WebSocket 서버로 전체 플로우를 검증했습니다.
- 자동 허용/기존 API/사용자 동작이 필요한 센서 권한 방식 3종에서 통과했습니다.
- 물의 양에 따른 영상 진행·배속, 기울임 중단, 물 완전 배출, 영상 조기 종료 방지, 재접속, 초기화, TD 1회 신호를 확인했습니다.
- 버디3 GPU에서의 GIF 표시와 실제 iPad 영상 디코딩/네트워크 지연은 배포 후 기기에서 확인해주세요.
